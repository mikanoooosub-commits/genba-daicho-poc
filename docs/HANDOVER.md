## 5. 守ること(このアプリの決まり)
- **会話ではなくファイルを正とする。**変えたら、同じコミットで `docs/architecture.md`・`docs/change-log.md`・関連の文書も直す(`poc-app/CLAUDE.md` §5)。
- **`.env*` を読まない・コミットしない。**`service_role` キーは使わない。
- **dev サーバーが動いているあいだは `npm run build` をしない**(`.next` を取り合って 500 になる)。検証は `npx tsc --noEmit` と `npm run lint` まで。本番ビルドは dev を止めてから。
- **物理削除をしない・`git push --force` をしない。**取り消しは論理削除+理由つき。
- 入居者名・担当者名は持たない(`poc-app/CLAUDE.md` §2)。データはすべて**架空**。実在の会社と紛らわしい名前を作らない。
- 文言は `natural-wording` で検査する。「業界初」などの NG 表現を書かない。
- 部品を足すときは、先に `docs/DESIGN-SYSTEM.md` に行を足し、`/design` に見本を足し、同じコミットでコードを書く。ライブラリを足すときは、名前・ライセンス・理由を PM に上げる(D82)。
- ログインは**ユーザーが行う**(Supabase の本人のアカウント。PL はパスワードを入力しない・探さない)。
