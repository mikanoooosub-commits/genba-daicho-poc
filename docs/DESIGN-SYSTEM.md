## 1. 原則

1. **現場でスマホ1分。** 屋外のスマホ・片手の親指で、1件を1分で記録できる。選ぶだけで済む形にし、初期値を入れ、押す場所は 56px 以上、「登録する」は画面の下に固定する。
   理由: 一人親方の事務は現場と移動の合間に行われる(D75)。入力が重いと続かない。
2. **色だけに頼らない。** 状態や注意は、色に加えて「形の違うアイコン」と「文字」で示す。白黒で印刷しても区別できる。
   理由: 屋外の強い光・色覚の違い・白黒の印刷で、色の差は読めなくなる。WCAG 1.4.1。
3. **1画面に、主な操作は1つだけ。** 主のボタン(深緑の塗り)は1つ。ほかは副・文字だけ・取り消しに下げる。
   理由: 何を先にやるかが一目で分かるため。段階A で、案件の詳細に主が2つあった(F-03)。
4. **人が決めることを、邪魔しない。** 状態を進める・金額を決める・取り消すのは人。アプリは提案と確認だけ出し、勝手に変えない。取り消しは理由つきで、記録は残る。
   理由: 「AIは間違えます。だから直す前提で作りました」が、この PoC の核(poc-app/CLAUDE.md §4)。
5. **数字は等幅で、右に揃える。** 金額・数量・日付は `.num`(`tabular-nums`)。金額には ¥ と桁区切り、税込か税抜かを見出しか表の上に書く。
   理由: 桁がそろうと、読み間違いと見比べの手間が減る。請求の画面では誤読が金額の誤りに直結する。

## 5. 状態と気づきの表し方

**1つの案件・請求に、状態のラベルは1つだけ。** 対象ごとに値が違うもの(日数・金額)はラベルにせず、「気づき」として文字とアイコンで別に出す。

| 状態 | 見た目(地/文字) | アイコン | 文字 | どこに |
|---|---|---|---|---|
| 依頼・見積中・**下書き**(見積) | 灰 / `#3D4A4C` | ○ | 依頼・見積中・下書き | ラベル |
| 受注・施工中・完了・**採用**(見積) | 薄い緑 / 深緑 | ◐ | 受注・施工中・完了・採用 | ラベル |
| 請求済・未入金・一部入金・**提出済**(見積) | 薄い青 / 青 | 時計 | 請求済・未入金・一部入金・提出済 | ラベル |
| 入金済・**確定**(見積の合計) | 薄い緑(緑) / 緑 | ✓ | 入金済 | ラベル |
| 失注 | 白・**点線の枠** / 灰 | 横線 | 失注 | ラベル |
| **見込み**(見積の額・まだ請求がない) | 文字だけ・「見積」と添える | — | 「¥96,800 見積」 | 金額の列 |
| 請求が未作成 | 橙の文字+行の左に橙の帯 | 三角に ! | 請求が未作成 | 気づき |
| 期日超過 | 赤茶の文字+行の左に赤茶の帯 | 八角形に ! | 期日超過 23日 | 気づき(段階4 から) |
| 期日まで | 青の文字 | 時計 | あと 7日 | 気づき |

- 色の意味: **青=お金を待っている、緑=済んだ、橙=人の作業が要る、赤茶=期限を過ぎた**。
- 「見積」の状態(下書き・提出済・採用・失注)は、案件の8つの状態とは別の対象なので、案件の状態ラベルと並べて出さない。見積の画面の中だけで出す。
- 案件の画面では、7 つの状態を1本の流れ(`.flow`)で見せる。済んだ段=✓、今の段=深緑の地。失注は流れの外。**スマホでは 4 列×2 行に折り返す**(はみ出さない。C-1 で反映済み)。

## 6. 文言の決まり

検査の手順は `natural-wording` スキル。この画面で決めたこと(段階A の文言検査 `docs/design-audit/wording.md` から):

| 決まり | 内容・理由 |
|---|---|
| ボタンは動詞で終える | 「登録する」「完了にする」。「OK」「はい」「送信」だけにしない。理由: 何が起きるかが分かる |
| 呼び名を1つに | 新しく作る=**登録**(書類は**作る**、明細・部屋は**足す**、施工は**記録**)/ 消す=**取り消す**(実際は消えず記録が残るので「削除」は使わない。済みは「取り消し済み」)/ 戻す=**元に戻す** / 直す=ボタン・見出しは**編集**、文中は「直せません」/ 変更を残す=**保存する** / やめる=**やめる**(「キャンセル」は使わない)/ 選ぶ=**選んでください** / 評価=**手応え** / 失敗=「〜できませんでした」 |
| 案件・物件 | 「案件」=1件の依頼〜入金、「物件」=建物。「現場」「建物」は画面に出さない(アプリ名「現場台帳」は変えない) |
| 依頼の言い方 | 命令形の連発を避け、理由を添える。例: 「工種が選ばれていません。1つ選ぶと記録できます」。1画面に「〜してください」が3回以上なら言い換える |
| 内部の記号を出さない | 決定番号(D38-7)・ファイル名(migration_009)・「v1」・「サーバー」・「論理削除」は画面に出さない。旧画面から移したものは「旧画面から移した案件」 |
| 英語を出さない | 外部サービスのエラー文は、日本語の文に置き換える |
| 数字と単位 | 値は `¥12,345`、入力欄のラベルは「(円)」。¥ と「円」を同じ文に混ぜない。請求は「請求(税込)」、明細は表の上に「金額はすべて税抜」。部屋は「N部屋」 |
| 日付 | 画面は `2026/8/18(火)`、帳票(印刷)は `2026年8月18日`。エラー文に `YYYY-MM-DD` を出さない。例は「10月6日」 |
| 括弧 | 半角 `( )` に統一 |
| 状態の「済」 | ラベルは「〜済」、文中は「〜済み」 |
| 空の状態 | 何が無いかを1文+次の一手のボタンを1つ |

## 7. アクセシビリティ

| 項目 | 基準 | 確かめ方 |
|---|---|---|
| 文字のコントラスト | 4.5:1 以上(大きい文字 3:1)。このアプリは本文 7:1 を目標 | トークン表の値を WCAG の式で計算。画面は `docs/design-audit/` の計測スクリプトで全文字を計算 |
| 部品の境目・フォーカスの輪 | 3:1 以上 | 同上 |
| フォーカス | 全部品に、黄+黒の二重の輪 | Tab キーで一巡して目で確かめる(自動では確かめられない) |
| 押す場所 | 44px 以上、スマホ1分は 56px 以上 | ブラウザで `getBoundingClientRect` を計測 |
| 最小の文字 | 14px(入力欄は 16px) | 計算済みの font-size を数える |
| ラベルと入力 | すべての入力欄に `label`(または `aria-label`) | 計測スクリプトで未結び付きを数える |
| 見出し | h1 は1つ。h2→h3 を飛ばさない。`<main>` は1つ | 同上 |
| アイコンだけのボタン | `aria-label` を付ける(並べ替え・アカウント) | 同上 |
| 色だけに頼らない | 状態は色+形のアイコン+文字 | 白黒にして見て判断 |
| 横スクロール | 375px で出ない | `scrollWidth` と `clientWidth` を比べる |

## 9. スキル `jp-business-ui` との関係(矛盾を残さないための確認)
このアプリの決まりは、スキルの考え方を当てた1つ目の実例。スキルの本文はこの案件の値を持たない(値は §2 が正)。B-2 の報告(`work-orders/WO-012-B2-report.md` §5)との照合結果:
| 論点 | スキルの考え方 | このアプリの決め |
|---|---|---|
| 余白の刻み | デジタル庁は 8px 単位。4px 刻みも可 | **4px 刻み**。理由: 表・チップ・フォームの内側など、8px では粗い所が多い業務画面のため(経験則) |
| 値が無い欄 | どちらかに決める | **表の値が無いセルは「—」**(案件の請求額など)。空欄にしない。理由: 「まだ無い」と「表示漏れ」を区別するため(経験則) |
| 無効のボタン | 無効にせず理由を添える(デジタル庁) | 無効にするのは「入力がそろうまで」「先に下書きの保存が要る」のとき。**押せない理由を近くの文か `title` で添える**(段階C で、無効のボタンに理由が付いていない所を直す) |
| フォーカスの輪 | 全部品同じ・地と 3:1 | `v2.css` は黄+黒の二重(デジタル庁のトークン値)。**見本 `design-samples/tokens.css` は橙の輪のまま**で食い違う → 見本を `v2.css` に合わせる(段階C) |
| 確認ダイアログ | `confirm()` を使わない。取り消せない・お金の操作だけ | 同じ。理由欄つき(D104-5) |
| スマホの下ナビ | 4〜5項目 | 4項目(D104-7) |
