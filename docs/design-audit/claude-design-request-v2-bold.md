## 貼る文
> 添付は、一人親方の原状回復・内装業者向けの業務アプリ「現場台帳」です。依頼から入金までを案件ごとに見る台帳で、現場のスマホと事務所のパソコンで使います。LP に事例として載せるので、**見て「これは使いたい」と思えるデザイン**にしてください。前回は「いまの見た目を整える」範囲で直しましたが、今回は**縛りを外します。大胆な案を出してください。**
>
> ### 変えてはいけないのは、これだけです(事実)
> - 画面に出る**情報の中身**(案件番号・物件・発注元・受付日・状態・請求・入金・見積の明細と合計・粗利など)。データを足したり、実在の人や会社を作ったりしないでください(すべて架空)。
> - できる操作の種類(登録・編集・状態の変更・見積を作る・請求を追加・取り消す…)。操作の**見せ方・順序・強弱は自由**です。
>
> ### それ以外は自由です
> 配置・情報の強弱・色の使い方・形・文字の組み方・余白・アイコン・図の使い方(数字をグラフや帯にする、など)・文言の言い回しまで、よりよい案があれば変えてください。**配色も、深緑×橙にこだわらなくて構いません。**ただし、提案資料(深緑×橙)と同じ事業者の道具に見えるほうが望ましいので、変えるなら理由を書いてください。
>
> ### 考え方の目安(縛りではなく、狙い)
> - 現場でスマホ1分で使える。屋外の光でも読める。
> - 次に何をするかが、一目で分かる。
> - 数字(粗利・合計・未入金)が、すぐ目に入る。
> - 一人親方が「自分の仕事を分かってくれている道具だ」と感じる。事務っぽさより、頼れる感じ。
> - 最低限の読みやすさ(文字が小さすぎない・指で押せる・色だけに頼らない)は守ってほしいです。ただし、これを理由に案を無難にしないでください。基準に届かない所は、あとで私たちが測って直します。
>
> ### 作ってほしいもの(画面は5つ。それぞれ**3案**。案ごとに一言のコンセプト)
> 1. 案件の一覧(PC 1280px)
> 2. 案件の詳細(スマホ 375px)
> 3. 見積の編集(PC 1280px。**入力中の下書き**。区分・内容・数量・単位・単価・金額の入力、行を足す、前回の見積から写す、合計)
> 4. 見積の編集(スマホ 375px。入力中の下書き)
> 5. 案件の登録(スマホ 375px。現場で1分で入れる。物件を選ぶ・発注元・種類・依頼の内容)
>
> 3案は、**互いに違う方向**にしてください(例: A=いまの延長で洗練 / B=数字とカードを主役にした思い切った案 / C=まったく別の発想)。
>
> ### 出力
> - 5画面×3案(HTML。静的でよい)と、案ごとのコンセプトの一言。
> - どの案を最も推すか、その理由。
> - トークンや部品に足したものの一覧(色の値・コントラスト比つき)。
> - 「Handoff to Claude Code」で渡す。無理なら HTML を書き出して `docs/design-audit/claude-design/v2/` に保存。

## 受け取ったあと(生成とは別の段階。ここで縛る)
1. **チェック(PL・機械的)**: 案ごとに次を測る。最小の文字・押す場所 44px・コントラスト・色だけに頼っていないか・横スクロール・トークン外の色・文言(情報の中身が欠けていないか)。結果は表にして、「基準に届かない所」と「直し方」を書く(届かなくても案は捨てない)。
2. **評価(PL・観点)**: LP での見栄え / 一人親方に響くか / 現場のスマホ1分 / 提案資料との一貫 / 実装との距離(いまの部品でどこまで作れるか)。
3. **判断(PM・ユーザー)**: 採る案・混ぜる案・採らない案を決める。**本番に入れるかは別の関所**(`design` ブランチの確認→マージ。研修の前後どちらかも、ここで決める)。
4. 採った案の実装は、いまの部品に当てはめる(生成 HTML をそのまま貼らない)。ここで初めて「壊さない」を条件にする。
