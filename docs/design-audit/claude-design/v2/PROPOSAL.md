## 2. 最も推す案: B(ただし一覧と見積の PC は A の表組みを混ぜる)

**B を推します。** 理由は4つ。

1. **狙いのうち「数字がすぐ目に入る」「次に何をするかが一目で分かる」を、いちばん強く満たす。** 詳細(スマホ)は最初の1画面に、粗利 48px と「請求を追加」の橙のボタンが両方入る。一覧は入金待ち ¥1,003,000 が 56px で頭にある。
2. **LP に載せたとき、遠目でこのアプリだと分かる。** 深緑の面+大きな数字+橙のボタンは、縮小した画像でも形が残る。A は整っているが、縮めるとふつうの業務画面に見える。
3. **提案資料と同じ事業者の道具に見える。** 深緑×橙のまま。変えたのは橙の明るさだけ(下の §4)。
4. **実装との距離が中くらい。** カード・合計・選ぶボタンはいまの部品の延長。C の「見積書そのものを直す」ほどの作り直しは要らない。

**B の弱い所(そのまま採らないほうがよい所)**

- **一覧のカードは、件数が増えると見比べにくい。** 13件で画面の高さが A の 1,402px に対して 1,795px。日付順に目で追うのは表のほうが速い。→ **一覧は「B の深緑のまとめ+A の表」**を勧めます。
- **見積(PC)の明細は1件が2段**(内容/数量×単価=金額)。6行で縦に長い。行数が多い見積では A の1行入力のほうが速い。→ **見積(PC)は「A の表+B の右の合計の塔」**を勧めます。
- **橙のボタンは、白い地との境目が 2.1:1。** 形として 3:1 に届かないので、墨の太い枠(2px)を必ず付ける。枠を外すと基準を割る。

**C から拾うとよい所**

- 一覧を「次にやること」の順に束ねる並べ方(見積を出す→施工する→請求を作る→入金を待つ→済んだ)。見た目とは別に、**並び順と見出しだけ** A・B の一覧に入れられる。
- 登録の一文(「さくらマンション の 203 で、管理会社A(架空) から、原状回復 の依頼。」)。B の下の要約の帯を、この一文に替えられる。
- 詳細の工程の線は、読むには一番分かりやすい。ただし操作が線の中に散るので、現場で「施工を記録」を探す手数は B より多い。

**A の位置づけ:** いちばん安全で、いちばん早く入る。B を採らない場合の受け皿で、B に混ぜる表組みの出どころ。

## 3. 3案に共通して変えたこと(言い回し・集計)

- **「気づき」を「次の一手」に言い換えた。** 完了=「請求を作る」、請求済=「入金を待つ」、入金済=「済み」。状態から決まる言い換えで、新しいデータではない。
- **「v1」を画面から外した**(「旧画面からの移行分」「旧画面から移した案件」)。DESIGN-SYSTEM §6 の決まりどおり。
- **施工の1件**を「日付+工種/内容・手応え 普通・担当 本人」に並べ直した。項目は同じ。
- **前回の施工の日付**を `2026-09-20` から `2026/9/20(日)` に(画面の日付の決まり)。
- **足し算で出した数字がある。** 一覧の「入金待ち ¥1,003,000(請求済 8件の合計)」「入金済 ¥140,000(4件)」「請求した ¥1,143,000(12件)」、見積の「小計の内訳(施工費 ¥80,460・商品代 ¥38,000・経費 ¥5,000・値引き −¥460)」。どれも画面にある数字の合計で、検算済み。**本番ではサーバーで計算した値を出すこと。**
- ボタンの言い回し: 「明細に」→「明細に足す」(A・B)/「写す」(C)、「登録する」→「この内容で登録する」(C)。「請求を追加」は変えていない。

**届いていない・確かめていない所(あとで測る所)**

1. B の橙のボタンと札は、白地・`bg` との境目が 2.1:1 と 1.9:1。枠(墨 2px)で形を出している。枠を細くする・外すと割れる。
2. 太さ 800 は、Windows の游ゴシックには無いので 700 で出る。B・C の数字は、Windows では画像より細く見える。
3. Hiragino・游ゴシックの実機では見ていない。折り返しが変わりそうな所: B-5 と A-5 の物件のタイル(9文字の物件名)、C-5 の一文、C-3 の上の帯。
4. フォーカスの輪は v1 のまま(黄+黒)。C の紙の地の上では黄が見えにくいはずで、黒の線だけが効く。Tab での一巡はしていない。
5. C の判子は 3度傾けてある。文字は読めるが、拡大表示での見え方は未確認。
6. 白黒での見え方は、帯グラフ(斜線・点線の違い)と状態(形の違うアイコン)で分けたが、15画面の白黒の画像は作っていない。

## 6. データと、入れていないもの

- **一覧と詳細**は、いまの画面の内容(13件、K2026-0016 さくらマンション 305)。一覧の 6〜13 行目は前回と同じく画像から読んだ値で、合計(¥1,003,000・¥140,000)もそれに引きずられる。
- **見積(下書き)と登録**は、添付の見本(`form-estimate-pc.png`・`quick-entry-sp.png`)の内容。いまの画面に下書きの画像が無かったため。**一覧・詳細とは別の案件**(K2026-0048 さくらマンション 203・M2026-0052)なので、5画面を通して同じ1件にはなっていない。登録の物件の候補は、いまの登録画面(`sp-cases-new.jpg`)の3件。
- **見本にあって入れていない操作:** 見積の「よく使う明細から選ぶ」。いまの画面にあるか確かめられなかった。あるなら「行を足す」の隣に置く。
- スマホの見積(A-4・B-4・C-4)は、「前回から写す」を折りたたみにしてあり、開いた中は「同じ部屋」の3件だけ。「同じ発注元」の見積(M2026-0050)は PC の画面にだけ出している。
- 見本の左メニューにあった「未入金・集計・CSV の書き出し・地図」は入れていない(いまの5項目に合わせた)。
- C-3 の見積書の差出人(サンプル内装 合同会社(架空)ほか)と発行日は、見本の印刷の見え方から。
- リンクの `href` はすべて `#`。動きは無い(`<details>` の開閉だけ動く)。
